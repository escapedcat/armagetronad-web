# M6 — The phone lag: measure it validly, rank the cheap levers, price the real fix

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reproducible measurement of the slowdown the maintainer feels on his phone, the cheap settings-only levers ranked against it with their gameplay cost stated, and real display lists priced — so the maintainer chooses a fix from numbers rather than from a story.

**Architecture:** No game-source change is planned. Everything is harness under `web/tools/perf/` (the seed is a git stash), evidence under `docs/evidence/m6-lag/`, and — only if a cheap lever wins and the maintainer says so — a touch-only config append in `web/shell.html` following the existing `applyTouchCameraTuning()` pattern. Display lists are *priced* in a design note, not built; building them is a milestone of its own.

**Tech Stack:** Unchanged — Emscripten 6.0.8, `-sLEGACY_GL_EMULATION`, Asyncify. Harness: `web/tools/drive-browser.mjs` (CDP, Node 22, no npm deps), `python3` for tables.

**Spec:** `PLAN.md` § "Phase 3 — minimal touch support", the dated block **"Then a real phone, 2026-09-03"**, fourth bullet and the paragraph **"This is M6."** — restated here so the plan travels alone:

> *"It lags — starts smooth, gets laggier the more I drive, and when I'm fast and close to a wall."* CPU-bound, not fill-bound: `?dpr=1`, a ninth of the pixels, felt identical to him. Two candidate mechanisms are in the source and neither is measured yet: unbounded wall trails re-submitted through the GL emulation every frame, and the rubber path's recursive `TimestepCore` when grinding. […] Establish reproducibility first; then A/B the cheap levers (`WALLS_LENGTH`, a frame cap, `FLOOR_MIRROR_INT 0`) against that baseline; then price real display lists in `eCompat.cpp` against the *measured* growth. Nothing milestone-sized is built without the maintainer's say.

## Global Constraints

- **A gate must prove the condition it measures actually held.** Every reported arm carries (a) a screenshot from late in a measured round showing trail geometry, (b) the `[PERF]` line's draw-calls-per-frame for the late window, and (c) `VALID` from `web/tools/perf/check-arm.mjs`. An arm without all three is not a number; it is written up as INVALID or not at all. This is the lesson of the first sweep, which measured an idle tutorial screen six times.
- **`MAX_FPS 1000` in every arm.** The shipped limiter pins frame time at 16.7 ms and hides every cost; these are costs, not rates. Say so in every table.
- **CPU-throttle after boot, before measuring, with `cpu:RATE`** (`drive-browser.mjs`). Unthrottled, this desktop has ~8x a phone's headroom and reads flat. **Rate 6 unless a task says otherwise; the rate is a column in every table.** The observed slowdown at rate 6 was ~2.5–3x, not 6x; report what you see, not the setting.
- **Round 1 is never measured.** It is where the tutorial is cleared (`key:Right:1`, `key:Left:1` after `[L] NEW_ROUND` — without them the match never starts and the arena stays empty) and where the throttle is switched on. Rounds 2 and 3 are the measurement.
- **Desktop numbers are desktop numbers.** Early-vs-late *ratios* and lever *deltas* are the transferable results; absolute milliseconds are not. Every README says so once, plainly.
- No game-source change in Tasks 1–5. Task 6 may touch `web/shell.html` only. If any task finds it must touch `src/`, stop and report: `make -f web/Makefile dedicated` must still produce **2,488,298 bytes AND md5 `9718a2a64978cb6e9b95ea2f0454cca5`**, and that is a different milestone's risk.

- Same-file citations name a symbol, never a line number. Any sentence that counts or enumerates says what it counted.
- **Commit messages containing backticks use `git commit -F <file>`.** Never a `Claude-Session:` trailer.

## What reconnaissance established — do not rebuild these assumptions

Measured on 2026-09-03 unless a source file is cited.

1. **The harness must press keys or nothing is measured.** With no steering input after `[L] NEW_ROUND` the tutorial overlay stays up and the arena stays empty for the whole round (screenshot: 30 s in, no trail anywhere, score 0–0). Two presses — `key:Right:1`, `key:Left:1` — make it live: a wall was on screen and an AI moving at 20.3 within 19 s. The first sweep lacked this and read 6.4–8.2 ms flat in all six arms.
2. **Config patching reaches the game.** Appending lines to `/data/webdefaults/autoexec.cfg` via `Module.FS.writeFile` before `window.AA_START()` took effect: `SP_SIZE_FACTOR 6` + `SP_NUM_AIS 7` cost +0.9 ms over `SP_SIZE_FACTOR 3`. `web/shell.html`'s `applyTouchCameraTuning()` is the shipped, touch-only form of the same mechanism, with a `?cam=` override for measurement on any device.
3. **First valid reproduction, cpu:6, `SP_SIZE_FACTOR 6`, `SP_NUM_AIS 7`:** round 2 went 20.0 → 27.7 ms p50 early→late (ratio 1.39), p90 23.1 → 41.3 ms, 29 fps on screen with real trails; round 3 was flat (22.6 → 23.3, ratio 1.03). Cross-round: round-2-early 20.0 vs round-3-early 22.6. **Intermittent. One run is not a baseline.**
4. **`?dpr=1` felt identical on the phone** → CPU-bound. A resolution setting is out of scope.
5. **Mechanism 1 (render):** `gCycle::wallsLength = -1.0f` (`gCycle.cpp`, "the maximum total length of the walls") — trails never expire; `SP_WALLS_LENGTH` is a real setting (`gGame.cpp`, `sp_wl`). `gWall.cpp` is built around `gCycleWallsDisplayListManager`, but display lists are five stubs in `src/emscripten/eCompat.cpp` (`glGenLists` returns 0; Emscripten's `libglemu.js` has none of the five names), `sr_useDisplayLists` defaults to `rDisplayList_Off` (`rScreen.cpp`) and the only code that ever set it — the NVIDIA vendor test — is compiled out under `__EMSCRIPTEN__`. Forcing `USE_DISPLAYLISTS` would trip `tASSERT( list_.list_ )` in `rDisplayListFiller::Start`. So every wall segment is re-submitted through the JS emulation every frame; the fallback in `rDisplayList::OnCall` is graceful (returns false, caller re-renders), not thrashing.
6. **Mechanism 2 (simulation):** in `gCycleMovement::TimestepCore` the rubber path computes `numTries`, and under `gRecursionGuard guard( recurse )` recurses into `TimestepCore( runOutTime, false )` then `TimestepCore( currentTime )` — "need many attempts". Fed by `gSensor` grid scans. Scales with walls *near* the cycle, not total walls. `gWall.cpp` has no distance-based detail, so proximity does not make the *renderer* work harder.
7. **Native Armagetron on non-NVIDIA hardware also runs with lists off.** The port did not remove a feature; the JS emulation makes per-vertex submission far dearer than a native driver's.
8. **Harness facts.** `web/tools/drive-browser.mjs` steps: `wait:MS`, `eval:EXPR` (one line), `until:N:MS:TEXT`, `tap:SELECTOR`, `key:NAME[:N]` (300 ms per press; `Right`, `Left`, `Enter`, letters), `shot:NAME`, `mark:TEXT`, `cpu:RATE`. Flags: `--headed --mobile 915,412,3 --out DIR --url URL --script-file F`. URL: `http://localhost:8000/armagetronad.html?autostart=0&touch=1` served by `python3 -m http.server 8000 --directory web/dist-m1`. The console transcript lands in `DIR/console.log`; an `eval:` result is logged as `eval … => "<result with \" escaped>"`.
9. **The seed.** `git stash list` shows `M6 seed: first perf sweep (INVALID: never drove the cycle) + its tooling` containing `docs/evidence/phone-round2/perf/{run-perf-sweep.sh,summarise.py,arm.steps.tmpl,grind.steps.tmpl}` plus six result directories. **The tooling is the seed; the results are not evidence of anything and are not committed.** `run-perf-sweep.sh`'s header explains why `SP_SIZE_FACTOR` is harness setup (the shipped −3 arena ends a round in eight seconds) and why the `\\n` in its `sed` is load-bearing.

- [ ] **Step 2: Write the sampler — frames AND geometry**

`web/tools/perf/sampler.js`. One expression; `/* */` comments only, because `run-arm.sh` strips newlines to fit it into one `eval:` line.

```js
(() => {
  /* One frame = one flush/finish from rSysDep::SwapGL. Per frame we keep the
     timestamp, the number of drawArrays/drawElements calls, and the bytes that
     went through bufferData/bufferSubData: draw calls and bytes are the direct
     measure of "geometry re-submitted through the emulation this frame", which
     is mechanism 1 -- so a frame that gets slower while its draw calls stay
     flat is NOT the renderer. */
  const N = 600000;
  const S = { t: new Float64Array(N), draws: new Uint32Array(N), bytes: new Float64Array(N), n: 0,
              marks: [], cur: { draws: 0, bytes: 0 } };
  window.__fps = S;
  const wrap = (C) => {
    if (!C) return; const P = C.prototype;
    for (const m of ['flush', 'finish']) { const o = P[m]; if (!o) continue;
      P[m] = function () {
        if (S.n < N) { S.t[S.n] = performance.now(); S.draws[S.n] = S.cur.draws; S.bytes[S.n] = S.cur.bytes; S.n++; }
        S.cur.draws = 0; S.cur.bytes = 0; return o.apply(this, arguments); }; }
    for (const m of ['drawArrays', 'drawElements']) { const o = P[m]; if (!o) continue;
      P[m] = function () { S.cur.draws++; return o.apply(this, arguments); }; }
    for (const m of ['bufferData', 'bufferSubData']) { const o = P[m]; if (!o) continue;
      P[m] = function () { const d = (m === 'bufferData') ? arguments[1] : arguments[2];
        S.cur.bytes += (d && d.byteLength) ? d.byteLength : (typeof d === 'number' ? d : 0);
        return o.apply(this, arguments); }; }
  };
  wrap(window.WebGLRenderingContext); wrap(window.WebGL2RenderingContext);
  const cl = console.log.bind(console);
  console.log = function () { const s = (arguments.length && typeof arguments[0] === 'string') ? arguments[0] : '';
    if (s.indexOf('[L] ') === 0) S.marks.push([performance.now(), s]); return cl.apply(null, arguments); };
  return 'sampler armed: frames, draw calls, buffer bytes';
})()
```

- [ ] **Step 3: Write the report — early vs late, ms AND draws, per round**

`web/tools/perf/report.js`. `TAGHERE` and `CPURATE` are substituted by `run-arm.sh`.

```js
(() => {
  const S = window.__fps, n = S.n;
  const nr = S.marks.filter(m => m[1].indexOf('[L] NEW_ROUND') === 0).map(m => m[0]);
  const rw = S.marks.filter(m => m[1].indexOf('[L] ROUND_WINNER') === 0).map(m => m[0]);
  const q = (a, p) => { if (!a.length) return null; const s = a.slice().sort((x, y) => x - y);
    return s[Math.min(s.length - 1, Math.max(0, Math.round(p * (s.length - 1))))]; };
  const r2 = (x) => (x == null) ? null : Math.round(x * 100) / 100;
  const win = (t0, t1) => {
    const ix = []; for (let i = 0; i < n; i++) if (S.t[i] >= t0 && S.t[i] <= t1) ix.push(i);
    const d = []; let dr = 0, by = 0;
    for (let k = 1; k < ix.length; k++) d.push(S.t[ix[k]] - S.t[ix[k - 1]]);
    for (const i of ix) { dr += S.draws[i]; by += S.bytes[i]; }
    const f = ix.length || 1;
    return { frames: ix.length, ms_p50: r2(q(d, .5)), ms_p90: r2(q(d, .9)),
             fps: r2(ix.length / ((t1 - t0) / 1000)), draws_per_frame: r2(dr / f),
             kb_per_frame: r2(by / f / 1024), hitches_over_50ms: d.filter(x => x > 50).length }; };
  const perSec = (t0, t1) => { const ms = [], dr = [];
    for (let k = 0; k * 1000 < t1 - t0; k++) { const w = win(t0 + k * 1000, Math.min(t1, t0 + (k + 1) * 1000));
      ms.push(w.ms_p50); dr.push(w.draws_per_frame); } return { ms_p50: ms, draws_per_frame: dr }; };
  const rounds = [];
  for (let i = 0; i < Math.min(nr.length, rw.length); i++) {
    const t0 = nr[i], t1 = rw[i], len = (t1 - t0) / 1000; if (len < 8) continue;
    const e = win(t0, t0 + 5000), l = win(t1 - 5000, t1), all = win(t0, t1);
    rounds.push({ round: i + 1, length_s: r2(len), early_5s: e, late_5s: l,
      ratio_ms: e.ms_p50 ? r2(l.ms_p50 / e.ms_p50) : null,
      ratio_draws: e.draws_per_frame ? r2(l.draws_per_frame / e.draws_per_frame) : null,
      hitches_over_50ms: all.hitches_over_50ms, per_second: perSec(t0, t1) }); }
  return '[PERF] TAGHERE ' + JSON.stringify({ arm: 'TAGHERE', cpu_rate: CPURATE, frames: n,
    rounds_started: nr.length, rounds_won: rw.length, rounds });
})()
```

- [ ] **Step 5: Write `run-arm.sh`**

```sh
#!/bin/sh
# sh web/tools/perf/run-arm.sh <set-dir> <arm> <cpu-rate> '<autoexec lines, \\n-separated>'
# e.g. sh web/tools/perf/run-arm.sh docs/evidence/m6-lag/task1-rig base 6 'SP_SIZE_FACTOR 6\\nSP_NUM_AIS 7'
# Serves nothing: run `python3 -m http.server 8000 --directory web/dist-m1` first.
# THE DOUBLE BACKSLASH IN THE 4TH ARGUMENT IS LOAD-BEARING: it lands inside a JS
# string literal in a one-line eval: step; a real newline there splits the step.
set -e
SET=$1; ARM=$2; RATE=$3; CFG=$4
[ -n "$CFG" ] || { echo "usage: $0 <set-dir> <arm> <cpu-rate> '<autoexec lines>'" >&2; exit 2; }
URL='http://localhost:8000/armagetronad.html?autostart=0&touch=1'
D=$(dirname "$0"); OUT="$SET/$ARM"; mkdir -p "$OUT"
SAMPLER=$(tr -d '\n' < "$D/sampler.js")
REPORT=$(tr -d '\n' < "$D/report.js" | sed -e "s|TAGHERE|$ARM|g" -e "s|CPURATE|$RATE|g")
awk -v S="$SAMPLER" -v R="$REPORT" -v C="$CFG" -v T="$ARM" -v P="$RATE" '
  { gsub(/SAMPLER/, S); gsub(/REPORT/, R); gsub(/CONFIGLINES/, C); gsub(/TAGHERE/, T); gsub(/CPURATE/, P); print }
' "$D/arm.steps.tmpl" > "$OUT/steps.txt"
node web/tools/drive-browser.mjs --headed --mobile 915,412,3 --out "$OUT" --url "$URL" \
     --script-file "$OUT/steps.txt" > "$SET/$ARM-driver.txt" 2>&1 || true
grep -h '\[PERF\]' "$OUT/console.log" | tail -1 | cut -c1-200 || echo "$ARM: NO PERF LINE"
node "$D/check-arm.mjs" "$OUT/console.log"
```
Note `awk` `gsub` treats `&` in the replacement specially and the sampler contains `&&`: if the substituted steps file shows a mangled `&`, escape with `gsub(/&/,"\\\\&",S)` before use — test by grepping `steps.txt` for `S.cur.draws++`.

- [ ] **Step 6: Write `check-arm.mjs` — the proof gate**

```js
#!/usr/bin/env node
// Exit 0 only if this arm's console.log PROVES the condition it measured held.
// A [PERF] line alone is not proof: the first sweep had six of them from an
// empty arena. Draw calls per frame in the late window are the geometry proof;
// the floor is calibrated in Task 1 Step 8 and recorded here with its provenance.
import fs from 'node:fs';
const EMPTY_ARENA_DRAWS_PER_FRAME = 0;   // Step 8 replaces this with the measured round-1-idle figure
const log = fs.readFileSync(process.argv[2], 'utf8');
const m = [...log.matchAll(/\[PERF\] \S+ (\{.*\})"\s*$/gm)].pop();
if (!m) { console.log('INVALID: no [PERF] line'); process.exit(1); }
const d = JSON.parse(m[1].replace(/\\"/g, '"'));
const keys = (log.match(/\[harness\] key (Right|Left)/g) || []).length;
const measured = d.rounds.filter(r => r.round >= 2 && r.length_s >= 30);
const problems = [];
if (keys < 2) problems.push(`only ${keys} tutorial key presses logged (need Right and Left)`);
if (!(d.cpu_rate >= 1)) problems.push('no cpu_rate');
if (measured.length < 2) problems.push(`${measured.length} measured round(s) >= 30 s (need rounds 2 and 3)`);
for (const r of measured) {
  if (!(r.late_5s.frames >= 30)) problems.push(`round ${r.round}: ${r.late_5s.frames} frames in the late window`);
  if (!(r.late_5s.draws_per_frame > EMPTY_ARENA_DRAWS_PER_FRAME * 1.25))
    problems.push(`round ${r.round}: ${r.late_5s.draws_per_frame} draws/frame late is not above an empty arena (${EMPTY_ARENA_DRAWS_PER_FRAME})`);
}
if (problems.length) { console.log('INVALID: ' + problems.join('; ')); process.exit(1); }
console.log(`VALID: ${measured.length} rounds; late ms p50 ${measured.map(r => r.late_5s.ms_p50).join('/')}; late draws/frame ${measured.map(r => r.late_5s.draws_per_frame).join('/')}`);
```

### Task 5: Price real display lists — a design note, no code

**Files:**

- [ ] **Step 1: What a display list would have to capture**

From `libglemu.js`, describe the immediate-mode path: where vertex data accumulates, where it is flushed to `drawArrays`, and what state (texture binding, colour, client-state/vertex format, matrices) is read *at flush time*. Then, from the GL spec semantics `rDisplayList.cpp` relies on: `GL_COMPILE` captures **values**, not references; `GL_COMPILE_AND_EXECUTE` (`rDisplayList_CAC`) draws while recording; `glCallList` replays with the *current* matrices but the *recorded* colours/texcoords; `glDeleteLists`. - [ ] **Step 2: Two implementation shapes, costed**

(a) **In `eCompat.cpp`**: record by intercepting the emulation's flush (is there a hook? if not, say so — that is the finding), store per-list VBOs + per-batch state, replay with `drawArrays`. (b) **In a JS library override** of the relevant `libglemu.js` functions (`--js-library`), recording at the point the emulation already has the batched data. For each: files touched, rough LOC, the three riskiest semantics (state at record vs replay; CAC; deletion while filling), how it interacts with `-sASSERTIONS=1`, and how it would be gated (`USE_DISPLAYLISTS` remains a runtime setting; the NVIDIA probe stays compiled out).

Compare with Task 4's best cheap lever. Recommend **go / no-go / not yet**, in one paragraph, with the reason. No code is written in this task; if the note finds a one-line experiment worth running (e.g. counting how many `glCallList` sites would fire with lists on, via a counting stub), it describes it and stops.

    // page appends to the preloaded autoexec.cfg before main(), only when the
    // primary input is a finger, so a desktop visitor's file is byte for byte
    // the shipped one. ?walls=N overrides on any device (0 = stock, unlimited),

        const q = readNumberParam('walls', 0, 100000);
        n = q !== null ? q : (window.AA_TOUCH ? WALLS_TOUCH_LENGTH : 0);
        if (!n) { console.log('[PERF] stock trails (unlimited)'); return; }
